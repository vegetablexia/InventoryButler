# Inventory Butler · 物品管家

给 Minecraft 的物品栏加一套泰拉瑞亚风格的**管理工具**：**一键整理**、
**收藏锁定**、**归位标记**，外加会跟着操作变形的**像素鼠标指针**。

- 游戏版本：Minecraft **26.2**（Fabric）
- 运行环境：**客户端 + 服务端都要安装**
- 依赖：Java ≥ 25、Fabric Loader ≥ 0.19.3、Fabric API ≥ 0.155.0
- 协议：MIT

> **名字的由来**：这几个功能合起来就是一位管家做的事 —— 帮你收拾房间（整理）、
> 把贵重品锁进保险柜（收藏）、记住每件物品自己的位置（归位）。
> mod id 为 `inventorybutler`，配置文件在 `config/inventorybutler.json`。

---

## 功能一览

| 功能 | 默认操作 | 一句话说明 |
| --- | --- | --- |
| **一键整理** | 鼠标中键 | 整理主背包 27 格（快捷栏默认不动），打开储存容器时容器内部也一起整理；容器可用指令切换「原位堆叠」；成功时不弹提示 |
| **收藏锁定** | Alt + 左键 | 金色边标跟着物品走：丢不掉、整理时不被挪走、Shift 也移不进容器 |
| **归位标记** | Alt + 右键 | 给格子定一个「家」：四角高对比白色角标始终可见，物品离开后另有半透明占位图标，回来时优先住回这一格 |
| **像素指针** | 按住 Alt | 指针指着可收藏的槽位时变成金色星星，抬手前就知道点下去会发生什么 |
| **界面内提示** | 自动 | 轻提示画在容器界面上方居中，界面开着也看得见；界面外仍走动作栏 |

整理键和收藏键可以在 `选项 → 控制 → 按键绑定 → 物品管家` 里改；
归位固定为 **Alt + 右键**（只对玩家背包 0-35 格有效）。

---

## 安装

1. 安装 **Fabric Loader ≥ 0.19.3** 与 **Fabric API ≥ 0.155.0**；
2. 把 `inventorybutler-1.0.14.jar` 放进 `mods/` 文件夹；
3. **服务端也要放同一个 jar**，联机时两端都要装（原因见「多人游戏」一节）。

单人游戏内置的服务端会自动加载本 mod，开箱即用。

## 按键与操作

| 操作 | 效果 |
| --- | --- |
| **鼠标中键**（可改绑） | 一键整理：主背包 27 格 + 当前打开的储存容器（两块区域各自整理，不混排） |
| **Alt + 左键** 点槽位 | 收藏 / 取消收藏（槽位四条边出现金色描边） |
| **Alt + 右键** 点玩家背包格 | 打 / 取消「归位标记」（箱子、护甲、副手格无效，此时 Alt+右键仍是原版操作） |
| **按住 Alt** | 指针变**金色星星**，只在指着能生效的槽位时才变形 |

> **创造模式物品栏**：中键仍归原版「复制物品」，不做一键整理；收藏 / 归位只认真正的
> 玩家背包格 —— 物品选择页里是底部快捷栏，「物品栏」页里是整块背包。
>
> **文本框有焦点时热键让路**：铁砧改名框、创造模式搜索框这些输入框里打字时，
> 改绑到键盘键上的热键都归输入框。

## 一键整理

### 整理范围

- **玩家背包**：默认只整理主背包 27 格（背包下标 9-35）。快捷栏 9 格保持你的摆位，
  护甲、副手、合成格永不参与。把 `sortIncludeHotbar` 设为 `true` 可以让快捷栏一起排序。
- **打开的储存容器**：容器里的物品**只在容器内部**排序合并，不会和背包混在一起。
  只认四种原版纯储存菜单：
  - 箱子 / 木桶（`ChestMenu`）
  - 潜影盒（`ShulkerBoxMenu`）
  - 发射器 / 投掷器（`DispenserMenu`）
  - 漏斗（`HopperMenu`）

  工作台、熔炉、铁砧、酿造台这些界面的槽位各有语义（合成、烧炼、输入顺序），
  整排排序会把它们搅乱，所以一律不参与；模组给箱子类菜单追加了特殊槽位的子类也不参与。
- **只认 GUI 范围内的中键**：JEI / EMI 的物品列表、书签栏、配方书都在容器界面之外，
  在那里按中键不会触发整理，不会抢别的 mod 的操作。

### 容器整理模式（指令切换）

打开储存容器时，「容器里的物品怎么落位」有两种模式。每个玩家单独选择，默认是旧的分类整理：

| 模式 | 指令 | 容器里的行为 |
| --- | --- | --- |
| **分类整理（旧版）** | `/inventorybutler sortmode category` | 合并同类项后按「分类 → 物品 id → 数量」重新排序 |
| **原位堆叠** | `/inventorybutler sortmode topmost` | 同种物品只往它当前最靠上的那一堆上加；那堆满了再往下一个同种格；物品种类不换格，空出来的同种格保持为空 |

`/inventorybutler sortmode` 不带参数可以查看自己当前模式。模式按玩家保存在
`config/inventorybutler.json` 的 `playerSortModes` 里，不需要 OP 权限。

> 原位堆叠只作用于**打开的储存容器**；玩家背包始终按分类整理。它只合并同种物品，
> 不会把空格压到底部，也不会把一种物品搬到另一种物品的格子上。

原位堆叠的例子（3×3 箱子）：

```text
整理前                 整理后
[石5] [泥10] [   ]     [石8] [泥30] [   ]
[钻2] [泥20] [   ] --> [钻2] [   ]  [   ]
[石3] [   ]  [苹果4]   [   ]  [   ]  [苹果4]
```

石头最靠上的堆在第一格、泥土在第二格；合并后它们仍留在原格，只是数量变了。

### 分类整理模式的规则（默认）

1. 收藏物钉在原槽位（由 `favoriteProtectFromSort` 控制），不进入排序池；
2. 归位预留格先留给它对应的物品；池子里没有这种物品时，这一格留空；
3. 其余物品先合并同类项，再按 **分类 → 物品 id → 数量（多的在前）** 顺次填回空格。
   分类顺序是「方块 → 工具 / 武器 → 盔甲 → 药水 / 桶 / 炖菜 → 其他」；
4. 整理后会兑现**快捷栏里的归位预留格** —— 即使快捷栏不参与排序，
   标记在快捷栏的物品也会被送回自己的格子。

### 不丢东西

整理分「先算清、再落盘」两步：玩家背包和打开的容器都各自先算清、确认放得下之后才动这一块。
万一因为异常物品栈（例如单格数量超过 `maxStackSize`）真的放不下，会**整单放弃这一块、该区域一点不动**，
并提示「背包状态异常，整理已取消」，而不是静默丢掉多余的物品。

整理成功时不弹任何提示（高频操作，弹字反而挡视线）。

### 服务端没装本 mod 时

整理、收藏、归位都需要服务端配合。客户端检测到服务器没有本 mod 时，会提示
「服务器未安装物品管家，此操作不可用」，而不是让你按了没反应。

## 收藏锁定

**Alt + 左键** 给指向的物品打上收藏标记：槽位外框出现一圈**金色描边**（四条边各一段，
四角留空，不压物品图标和数量）。

收藏标记挂在**物品本身**上（自定义数据组件 `inventorybutler:favorite`），
所以物品在背包、箱子之间移动，甚至被丢到地上、死亡掉落，标记都还在 —— 和泰拉瑞亚一致。

### 保护范围

| 场景 | 结果 |
| --- | --- |
| 界面关着按 Q / Ctrl+Q | 拒绝，弹提示 |
| 界面开着按 Q | 拒绝，弹提示 |
| 点到界面外，把光标上的收藏物丢出去 | 拒绝 |
| Shift + 左键把收藏物**移进容器** | 拒绝，弹提示 |
| 从容器把收藏物**拿回背包**、在背包内部换格 | 允许 |
| 一键整理 | 收藏物钉在原地，不参与排序（默认） |
| 手动拖拽 / 手动放置 | 允许 —— 玩家的手动摆放永远优先 |

> **Shift 保护看的是目的地**：只有目的地全是玩家自己的背包格才放行；只要混进一个
> 外部容器格就整次拦下。同一个背包格在背包界面里是「内部换格」，在箱子界面里却是
> 「搬进箱子」，只看来源格会误伤前者。

### 两个副作用

- 带收藏标记的那一叠**无法与普通同类物品合并**（数据组件不同，原版视为不同物品栈）——
  这正是「锁定」想要的效果，收藏的那一叠不会被自动并走。
- 关掉 `favoriteEnabled` 后，边框、指针和**所有收藏保护**一起失效；
  只想放行丢弃和 Shift 搬进容器，可以只关 `favoriteProtectFromDrop`（它同时控制这两条保护）。

## 归位标记

给物品在背包里指定一个固定的家。和收藏是两回事：收藏管「不许动」，归位管「放哪儿」。

### 怎么用

1. 鼠标指着背包里某一格（快捷栏 0-8 或主背包 9-35）；
2. **Alt + 右键** —— 这一格从此「属于」格里那个物品；
3. 打上标记后，格子四角立即出现**加粗的白色角标（带深色外衬）**；物品离开后，格子上还会显示**半透明物品图标**（只画图标，无数量、无耐久条）；
4. 物品回到背包时**优先住回这一格**。

触发归位的时机：

- **Shift 快速移动**：从容器拿回背包、在背包内部（主背包 ↔ 快捷栏、护甲格）快移都算。
  物品会**直接落进预留格**，不会先在默认格闪一下；
- **捡起地上的掉落物**（含 `/give`、合成产物）；
- **一键整理**（整理后它一定落在自己的预留格里）。

匹配**只看物品本身**（`ItemStack.getItem()`），忽略附魔、改名、耐久。
取消：指着那格再 Alt+右键（格子里是空的也行）。
「一个物品只有一个家」—— 把同一物品标到另一格，旧标记自动解除。

从**预留格自己**往别处 Shift 移出是允许的（不然物品就挪不动了）；它的下一次
Shift 快移会再把它送回来。

### 规则与边界

- **收藏优先**：收藏物不会被自动搬进预留格，也不会被移出预留格；预留位上坐着收藏物时不归位。
- **手动拖拽优先**：归位只在「Shift 快移 / 拾取 / 整理 / 刚打标记」这些时刻插手，
  不做每 tick 强制吸回 —— 手动拖拽放下的物品不会被立刻弹回预留格。
- 归位只负责「把一份物品送回预留格」，**不会把散落各处的同类物品聚拢**。
- 搬运是**整格交换**，不做「找空位放」，永远不会因为背包满而丢东西。
- **四角高对比白色角标始终可见**：不管格子里有没有物品都画，标记不会因为在位而“消失”。
  角标 4px 长、2px 厚，外侧压 1px 深灰外衬，在右下角的纯白高光上也能看清；
  白色主体会压住物品外沿 1–2px，但数量数字和耐久条画在角标之后，不会被挡。
- 半透明占位图标只在格子**空着**时画；格子里有别的物品时不叠图标，免得看不清。
- 归位角标和收藏边标共用同一个槽位外框：收藏占四条边的中段，归位占四个角；
  同格同时出现时，金色中段两端各留 4px 给角标（比只有收藏时各多让 2px），
  拼起来仍是一整圈，像素上不重叠。
- 标记只活在**服务端内存**里：退出服务器 / 换世界即清空，重进需要重标。
- 标记只认玩家背包 0-35；箱子、护甲、副手格按 Alt+右键无效。
- 同步包只发**物品类型**，不把整份物品栈（附魔、成书正文等）发来发去。

## 指针与提示

### 金色星星指针

按住 **Alt** 且指针停在可收藏的槽位上时，指针换成 16×16 硬边像素画的金色星星；松手立刻恢复箭头。

- 界面空白处、铁砧输入框、创造模式的物品选择器上不换；
- 走原版自己的光标通道（`applyCursor` → `Window.selectCursor`），
  恢复箭头由原版自动完成，也不会和输入框的 I 型光标打架；
- 光标构建失败时只会关掉这个小功能并记一条日志，不影响其他功能。

### 界面内轻提示

收藏、归位、Shift 被拦这些提示几乎都发生在容器界面里，而原版动作栏挂在 HUD 上 ——
**容器界面打开时 HUD 不渲染**。所以提示分两条路：

- **容器界面开着**：画在 GUI 顶上方居中，原版底纹 + 带投影白字，
  淡入 150ms → 停留 2.2s → 淡出 400ms；
- **界面外**（例如走路时按 Q）：照旧走原版动作栏。

提示**排队**显示（最多积压 4 条，超出丢最旧的）；同一条重复触发只刷新计时，不重复排队；
同一种提示还有 1.2 秒节流，连按 Q 不会刷屏。关闭界面时清空队列，不会带到下一个界面。

## 配置

首次启动生成 `config/inventorybutler.json`。手动修改后需重启游戏；
用 `/inventorybutler sortmode` 切换容器模式会立即生效并写回文件。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `sortEnabled` | `true` | 一键整理总开关 |
| `sortIncludeHotbar` | `false` | `true` 时快捷栏 9 格也参与排序 |
| `favoriteEnabled` | `true` | 收藏总开关：关掉后边框、指针、**所有收藏保护**一起失效 |
| `favoriteProtectFromDrop` | `true` | 关掉后收藏物可以被丢弃、也能 Shift 搬进容器，只保留边框 |
| `favoriteProtectFromSort` | `true` | 关掉后整理会挪动收藏物 |
| `pinEnabled` | `true` | 归位标记总开关（Alt+右键、归位角标、归位逻辑、半透明图标） |
| `cursorIconsEnabled` | `true` | 关掉后指针不再变形 |
| `playerSortModes` | `{}` | 每位玩家的容器整理模式（`category` / `topmost`），由指令写入，不建议手改 |

> 配置**双端都会读**：客户端读它决定界面行为，服务端读它做权威校验 —— 联机时
> **服务器上的那份文件说了算**。
>
> 老版本遗留的鼠标 / 滚轮手势配置键已废弃，启动时发现会自动清理重写。

## 多人游戏

- **单人**：开箱即用。
- **联机 / 服务器**：**客户端和服务端都要装本 mod**。所有会改变物品的操作（收藏、整理、归位）
  都由服务端权威执行，客户端只负责按键翻译和界面绘制 —— 不会出现「你这边改了、服务端还在」
  的鬼影，也没有复制物品的风险。
- **为什么服务端也必须装**：收藏标记是一个自定义数据组件。服务端把带这个组件的物品发给
  没装 mod 的原版客户端会导致客户端不认识该组件而断开，所以不做「客户端单装」的兼容。
- 服务器没装本 mod 时，客户端仍可启动，但整理 / 收藏 / 归位都会提示不可用。
- 归位标记存在服务端内存里，玩家退出即清空；收藏标记跟着物品，下线也在。

## 与其他 mod 的兼容性

设计上尽量不碰别人管的东西：

- **不覆盖任何原版按键行为**：整理只在容器界面 GUI 范围内接管中键，JEI / EMI 面板和书签栏
  的中键操作不受影响；功能关闭或服务端没装 mod 时会把按键还给原版。
- **不改渲染管线**：收藏边框、归位角标和幽灵图标只通过原版容器界面的槽位绘制注入点叠加，
  不碰 Sodium / Iris 的渲染路径。
- **不动输入系统**：不拦截全局鼠标 / 键盘事件，和 InvMove、IMBlocker 这类输入类 mod
  没有目标重叠。
- **不排序模组容器**：只认四种原版纯储存菜单类本身，模组追加了升级格、锁定位等
  特殊槽位的子类一律不整理，避免搅乱它们的语义。
- 开发环境与 JEI、IMBlocker、InvMove、Sodium / Iris、Jade、Litematica 系、Xaero's、
  AppleSkin、Cloth Config / ModMenu、ReplayMod、NoChatReports、CustomSkinLoader、
  I18nUpdateMod、Chat Heads、More Chat History、mcwifipnp 共存安装；重点核对过
  JEI 的界面内事件与整理键的范围判定，未发现目标重叠。未做逐项实机联调，
  遇到异常请附日志反馈。
- **键位冲突**：如果另一个整理 mod 也把中键绑成整理，两边会各拦一次。到
  `按键绑定` 里把其中一个改掉即可。

## 已知限制

- 收藏物不能与普通同类物品合并（设计如此）。
- 归位标记只活在服务端内存里：退出 / 断线即清空，重进需重标。
- 归位标记只认玩家背包 0-35；不覆盖护甲、副手、箱子格。
- 预留格里放着别的物品时，只保留四角角标，不叠加半透明占位图标（避免盖住真实物品）。
- 预留格被别的物品占着时：从容器 Shift 拿回来的物品仍会被换回预留格（可能看到一次刷新），
  背包内部快移则不会强行换走占位物品；空格预留是直接落位，不会闪。
- 归位不聚拢散落的同类物品，只把其中一份送回预留格。
- 整理默认只动主背包 27 格；护甲、副手、合成格永不参与。
- 容器整理只覆盖箱子 / 木桶、潜影盒、发射器 / 投掷器、漏斗；工作台等功能界面和
  模组自定义容器不参与。
- 原位堆叠不会把空格压到底部；想让空格沉底、整体按分类排列，请用
  `/inventorybutler sortmode category` 切回。
- 容器整理模式只作用于打开的储存容器；玩家背包始终按分类整理。
- 创造模式物品栏不启用中键整理；收藏 / 归位只认真正的背包格（物品选择页是底部快捷栏，
  「物品栏」页是整块背包）—— 物品选择器里的物品种类格不参与。
- 客户端与服务端必须都安装本 mod；只有客户端时上述功能不可用。

## 构建

需要 JDK 25（Minecraft 26.1 起要求 Java 25）。`build.gradle` 声明了工具链，
正常不用手动设 `JAVA_HOME`：

```bash
./gradlew build        # 产物在 build/libs/inventorybutler-1.0.14.jar
./gradlew runClient    # 开发环境启动客户端
./gradlew runServer    # 开发环境启动服务端
```

### 启动前的 Mixin 静态自检

Mixin 0.8.x 有一个编译器抓不到的坑：`@Shadow` 的**字段**只会在目标类自己声明的字段里找，
不沿继承链（`@Shadow` 方法则会）。shadow 父类字段会「编译通过、一启动就崩」。
`tools/verify_mixins.py` 会对着 Minecraft jar 逐条核对：

```bash
python tools/verify_mixins.py --jar <path/to/client.jar> \
       --javap "C:/Program Files/Java/<jdk>/bin/javap.exe"
```

退出码非 0 就说明有会崩的地方。
